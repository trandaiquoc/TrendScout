# D5 admission, quota, cache and queue design

**Status (12/11/2026):** local synthetic admission/quota/cache/queue behavior has offline evidence for the demo; `DEMO_ACCEPTANCE=100%`. `PRODUCTION_MULTI_HOST_ACCEPTANCE=BLOCKED` and `D5_PRODUCTION_READINESS=PARTIAL`: current resources are personal, company infrastructure is not provided, and no real shared backing/two-host/supervisor run has occurred. Local/test synthetic Fetch uses a file-backed atomic store across independent processes, which does not protect a multi-host production deployment. The guarded Firestore adapter is not wired into production and was not tested against Firestore or its emulator. Do not point it at the owner's personal Firebase/Firestore project.

## Implemented offline foundation (2026-11-12)

`PublicAdmission` operates on an `AtomicStateStore` port. Its transaction atomically coalesces active jobs for the fixed plan, stores bounded idempotency receipts, applies global start rate and cooldown, and manages a due-job queue with fenced worker leases, heartbeat, expiry and bounded retry deferral. Per-attempt reservation charges both daily and monthly internal request/cost budgets; Google and Bing share a SerpApi pool, and pool-level in-flight slots are bounded. A duplicate receipt returns `REPLAY`, which never permits an outbound request; a lost commit acknowledgement must also never cause a send. A shared disable switch, policy fingerprint and backward-clock check fail closed. No existing provider entitlement, actual invoice or verified quota is implied by internal units. No anonymous endpoint can change this policy.

`LocalSQLiteAtomicStateStore` now provides file-backed transactions for explicit local/test synthetic compositions only. It uses SQLite `BEGIN IMMEDIATE`, WAL and full synchronous commits, owner-only database-file permissions, bounded JSON state, and rejects memory databases, live mode and production profiles. The port is shared by independent processes on the same host/local filesystem; SQLite is not a multi-host or production deployment store. The Firestore SDK adapter remains disconnected. No database migration or cloud resource was created.

`DistributedFetchWorker` claims one admission job, resolves a server-owned retention grant per configured source, checks each handler's declared mode against that grant, checkpoints bounded source progress under the current fence, resumes completed/in-progress source checkpoints after lease reclaim, supports deferred retry and persists validated normalized results with `LIVE` or `SYNTHETIC` provenance. `D5SourceHandlers` maps the three guarded query collectors and Wikimedia gateway into this worker; normalized rows are capped at 100 KB and any omitted rows are counted while the source is marked partial. Its optional `SharedCache` integration is deliberately synthetic-only in D5: a fresh synthetic result preserves `data_mode=SYNTHETIC` and reports `delivery_state=CACHED`; misses call the fixture adapter and store nonempty success/partial evidence under a grant-scoped key, including the selected Wikimedia date. Live cache reuse remains disabled pending D6 policy and revocation controls. An offline four-source test confirms the second worker execution does not send transport requests. The `DistributedPublicFetch` facade coalesces idempotent submissions, returns only bounded public status/result fields, charges a shared atomic status-poll budget and refuses handlers without an explicit `SYNTHETIC` declaration. It is exposed through explicit local/test synthetic API injection, which schedules one worker attempt as an ASGI background task. `DistributedWorkerRunner` provides an independently invocable polling loop with bounded idle delay and graceful shutdown; failures bubble up for an external process supervisor to restart. No process supervisor is deployed or configured. An ASGI integration now exercises the same atomic store through public admission, fenced queue/worker execution, all four guarded MockTransport adapters, cache write, readback and a second Fetch served as `CACHED` without additional outbound calls. Eight independent worker processes competing on one queued job produce at most one completed execution. Quota and per-provider concurrency tests also run across processes. These tests establish local multi-process coordination, not multi-host behavior.

`GuardedAttemptRunner` reserves, rechecks the lease/switch and only then constructs a request; errors are sanitized and uncertain outcomes stay conservatively charged. This primitive is not wired to real transports or public Fetch. A task paused after its last lease check can resume after a slot expires, and an external provider cannot enforce the internal fencing token. Strict per-provider concurrency under arbitrary process suspension therefore remains **unproven**; it requires a verified bounded egress design and cancellation/deadline enforcement before live use. A process-local clock is not a trusted distributed time service: regressions fail closed, but clock skew, forward jumps and worker suspension require deployment-specific validation. Provider slots expiring after a configured timeout are safe only if the eventual transport actually enforces that bound.

`FirestoreAtomicStateStore` is an injected, single-document SDK adapter with bounded document size and conservative unknown-commit errors. It is **not connected to the application**, and tests use fakes only: no Firestore service or emulator was contacted. Serialization and contention behavior, production IAM, transaction retry/unknown-commit handling, operational monitoring, database cost and actual multi-host behavior remain unverified. `LocalSQLiteAtomicStateStore` is a real local single-host adapter tested across independent processes, not a database migration, multi-host store or proof of Firestore behavior. Admission prunes canonical UTC quota windows only after they are older than the active day/month; unknown, malformed, or future keys are retained so corruption fails closed. This bounded-window behavior has an offline regression test. Provider-reported usage reconciliation is not implemented, and a single shared coordination document still has contention/size limits. A supervised worker runner, egress controls, proactive data-retention deletion and deployment backing remain open.

`SharedCache` uses the same atomic port with a hash over source/provider, query, plan fingerprint, market/language, time window, parser and policy. It keeps `SYNTHETIC` or `LIVE` origin independently of `CACHED`/`STALE`, preserves the original fetch time, rejects late overwrites, tightens but never extends the existing retention window, rejects common credential fields and URLs, and fails closed when given a revoked approval or backward time. Offline tests include concurrent process writers and the guarded worker handler path. A copied old grant is not revocable by this component, so durable policy rechecks and revocation races must be addressed before wiring live. Payloads still need provider-specific data minimization and approval; secret scanning is not a substitute for eliminating secrets at ingestion. Expired content is cleared when accessed, while proactive deletion, Firestore TTL, backups/PITR, provider-specific deletion obligations and full multi-host behavior require a separately verified deployment. Neither an empty document nor an on-read cleanup proves deletion from backups.

The offline suite verifies concurrent coalescing and shared budget across processes, hard process death after reservation, lease expiry/fencing, bounded deferral, per-pool in-flight limits, idempotent settlement, clock regression, policy mismatch and disabled switch. A transport must own all its outbound work and finish or cancel within the configured slot; background work and process suspension invalidate that assumption. These tests do not authorize live activation.

Public requests provide no URL, query, provider, budget or credential. A backend-owned plan and source approvals determine eligibility. Admission must atomically deduplicate, enforce global concurrency/cooldown, reserve request and cost budgets (including the shared Google/Bing SerpApi pool) and create durable work. An outbox or equivalent atomic handoff prevents lost queue messages. Workers need bounded leases, monotonically increasing fencing tokens, idempotent writes, durable progress, retry/deadline/page caps and crash recovery. Every physical provider attempt must have a durable reservation before execution; uncertain outcomes must be conservatively accounted for. Cache must preserve source scope, timestamps, policy version and permissible retention, distinguish stale/partial/unavailable and support deletion.

The existing Firebase/Firestore remains temporary behind storage and coordination ports; no database migration is authorized. Firestore transaction constraints, queue scanning/indexes, throughput, contention, size and security rules must be independently designed and tested for the chosen deployment; a transaction cannot atomically encompass an external HTTP request. An unconfirmed provider response after a crash must not cause unbounded or unaccounted retry. Process-local state, browser checks, Origin and IP limits cannot alone secure direct API clients, bots, multiple IPs or processes. Deployment requires layered abuse controls, alerts, kill switches and independent security review. Public live Fetch stays disabled until separately approved.

Offline tests must exercise concurrent admissions across processes, repeated idempotency keys, quota exhaustion, shared budgets, lease expiry, stale fencing, worker death around reserve/enqueue/request/commit, idempotent recovery, partial failure and cache expiry/deletion. Synthetic test models do not prove multi-host deployment properties without testing the actual adapter and runtime.
