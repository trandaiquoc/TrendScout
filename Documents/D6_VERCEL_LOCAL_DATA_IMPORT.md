The local LIVE Collections database was found at `%LOCALAPPDATA%\TrendScout\collections-v1\collections.sqlite`. A read-only Production overview on 2026-11-22 reported 929 saved unique keywords, so this is a merge into an existing Firestore snapshot, not an import into an empty Production database. After the Owner enabled the already-approved keyless impersonated ADC on 2026-11-23, a credentialed read-only dry run read Firestore snapshot version 4 and validated the planned merge. No data was applied.

The prepared tool is `Backend/scripts/import_local_collections_to_firestore.py`. It targets the existing `trendscout-192e4/(default)` database and reuses the local runtime's approved keyless impersonated client. It does not create credentials or change IAM.

Run from `Backend/`:

```powershell
python scripts/import_local_collections_to_firestore.py
```

The default is a dry run. Add `--apply` to commit after reviewing the per-table counts. Before applying, the tool writes a timestamped backup of the currently restored Firestore SQLite snapshot beside the local database, then merges with `INSERT OR IGNORE`. It aborts on incompatible table schemas, conflicting Collection or keyword identities, invalid SQLite integrity, or foreign-key errors. Snapshot version checks prevent a concurrent Firestore update from being overwritten.

The snapshot contract allows 80,000,000 expanded SQLite bytes and 3,700,000 gzip bytes. The compressed limit leaves the base64 JSON envelope below the existing 5,000,000-byte snapshot-blob budget. The blob adapter writes 196,608-byte chunks; Firestore's current 1 MiB document and 10 MiB API-request limits were checked on 2026-11-20 ([official Firestore quotas](https://firebase.google.com/docs/firestore/quotas)). Before publishing an oversized snapshot, Vercel compacts its temporary SQLite copy. If it still exceeds either bound, only the recomputable embedding `cache` table is cleared from that temporary copy before the limits are checked again; the request-local working database and user data are not modified. Snapshot failure logs report expanded and compressed byte counts without content. The local file is 72,351,744 bytes. An offline merge into a freshly initialized LIVE store, omitting `cache`, `algorithm_results`, and local `settings`, produced 10,498,048 SQLite bytes and 1,612,836 gzip bytes.
