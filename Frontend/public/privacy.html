1. Service and current status

TrendScout helps users review keyword candidates and their source evidence. It does not require a TrendScout account, Google sign-in, or Google OAuth. The hosted dashboard is served through Vercel. Its SQLite and legacy run writes stay read-only. A separate Wikimedia Fetch may run only when server policy and the shared Firestore quota ledger allow it; an unknown or invalid ledger blocks the request before it reaches Wikimedia. Other providers remain unavailable in this Vercel slice.

Publishing this policy does not enable a provider integration. YouTube remains separately gated by server configuration, applicable source approvals, and the user's acceptance of the current policy version.

2. YouTube API Services

If YouTube is enabled in a supported runtime and selected for Fetch, TrendScout may receive public video IDs and canonical watch URLs, titles, descriptions, channel IDs and names, publication times, thumbnails, broadcast status, result position, query scope, and collection timestamps. This feature does not request view counts or other video statistics.

The purpose is to display attributed YouTube evidence and Fetch status. YouTube records are excluded from keyword extraction, trend scoring, and product recommendations. A US region filter describes video availability or relevance; it does not establish where a creator or viewer resides or prove US demand.

Current owner-stated YouTube purpose and approval status: TrendScout is a personal US-market keyword discovery demonstration. Proposed YouTube features include public video metadata search, keyword extraction, topic categorization and source-specific trend analysis. Additional YouTube-derived analytics permission has not been granted; the restricted features remain disabled.

The API key is resolved by the server and is not sent to the browser. TrendScout does not access a user's Google account or private YouTube data. When the feature is enabled, the server requires acceptance of the exact current TrendScout policy version before a YouTube Fetch proceeds.

YouTube use is subject to the YouTube Developer Policies, YouTube Terms of Service, and Google Privacy Policy.

3. Other sources and data sharing

Depending on the runtime and the sources enabled by the operator, TrendScout can retrieve Wikimedia pageviews, Google Trends RSS, Google Search results, or Bing Search results through SerpApi. Providers receive the bounded query and request parameters needed to answer a selected Fetch. TrendScout's current source plans are server-curated and do not provide a free-text field for personal information.

TrendScout does not sell source records or use them for advertising. The application does not send collection text to a hosted generative-AI service. Provider processing is governed by the relevant provider's terms and privacy notice. When the Vercel Wikimedia Fetch is enabled, the server requests public Wikimedia pageview data and stores its bounded shared cache and job state in the existing Firestore database. It does not call Google, Bing, or YouTube in this slice.

4. Browser and user information

The browser stores display preferences (theme, language, selected Fetch defaults, and sidebar state) and, when required by the runtime, the accepted policy version. These values use browser local storage; clearing site data removes them. TrendScout does not store API keys in browser storage and does not configure analytics cookies.

The application has no user account or profile. A provider does not receive a user's identity, browser history, or location from the YouTube adapter. The hosting platform may process request metadata as described in Section 6.

5. Storage, cache, and Fetch history

On Vercel, SQLite and legacy run writes remain read-only. A separate Wikimedia Fetch uses the existing trendscout-192e4/(default) Firestore database for its bounded job history, cache, checkpoints, quota reservations, and refresh state. A local Windows installation continues to use SQLite by default; Firestore sharing is opt-in. Local SQLite files are not synchronized unless that shared runtime is explicitly configured.

If YouTube is enabled in that standalone implementation, video records remain in the YouTube-scoped cache and Fetch checkpoint only as needed to serve a result. Cache freshness is eight hours, the cache retention ceiling is seven days, and a completed Fetch receipt/checkpoint is retained for up to one hour. Startup and hourly cleanup remove expired YouTube cache and checkpoint data; request-time checks prevent expired checkpoints from being returned.

The Collections database does not store YouTube videos as keywords or scoring observations. It may store a source manifest and counts for a Fetch. Targeted YouTube deletion removes YouTube manifest entries and adjusts mixed-source counts. Fetch identifiers, quota reservations, refresh eligibility, and other non-content operational records may remain to prevent repeated requests and preserve operational history.

6. Hosting logs, diagnostics, and backups

Operator-provided hosting and access-log practice: The public dashboard is hosted on Vercel. The local demonstration uses synthetic data and temporary local storage. Browser localStorage keeps theme and language preferences. Exact hosting access-log retention has not yet been verified.

The Vercel-hosted dashboard may produce platform runtime and access logs. Vercel documents that runtime-log retention depends on the account plan; the plan's current retention and any external log drain are controlled by the account owner and are not verified by TrendScout. See Vercel Runtime Logs documentation. TrendScout's gateway is designed to keep API keys, full provider request URLs, and provider response bodies out of its sanitized diagnostics.

No automatic backup job for the standalone SQLite databases was found in the repository. Operators may make their own copies; the application cannot discover copies outside its known data directories. Backups and externally retained console output require separate review after a deletion request. TrendScout cannot remove a provider's copy of data.
