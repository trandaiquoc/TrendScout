## Provider route for the eligible source

The only currently eligible live route is the configured exact `:free` model on the reviewed Particle AI provider endpoint. Immediately before each inference, the OpenRouter adapter checks that the model and selected endpoint are present, active, zero-priced, support the required JSON Schema/request parameters, and have enough context/output capacity. Routing is pinned to Particle AI with `allow_fallbacks=false`, `require_parameters=true`, and `max_price.prompt=0` / `max_price.completion=0`. No paid endpoint, credits, BYOK, tools, or web search is permitted.

Current provider disclosures say Particle AI does not train on prompt/output content and uses zero retention for standard synchronous inference; OpenRouter's API privacy support page says prompts and completions are not logged by default, while metadata may be retained. PublicData does not require request-level ZDR, but it also does not allow public prompt/completion exposure. These published statements are policy evidence, not a guarantee of account settings or future behavior. Recheck the source and provider policies before live inference. ## Registry behavior

- Unknown source IDs and source IDs without an explicit transfer policy fail closed.
- `PUBLIC_DATA` source permission is the intersection of the policy registry, `TRENDSCOUT_AI_ALLOWED_SOURCES`, and `TRENDSCOUT_AI_TRANSFER_APPROVED_SOURCES`.
- The public input builder intersects field allowlists across every source represented in a canonical keyword group. A missing field grant removes the field; a missing source grant blocks that source.
- `TRENDSCOUT_AI_PUBLIC_DATA_COLLECTION_IDS` is a separate, server-side allowlist for public-classified Collection names/descriptions. Empty means no Collection text is sent. Request-supplied `research_constraints` are rejected for PUBLIC_DATA until a server-side public classification exists.
- `STRICT_PRIVATE` continues to require `data_collection="deny"` and `zdr=true`; it never falls back to PUBLIC_DATA. `PUBLIC_DEMO` remains local/test-only synthetic data in its attested isolated PostgreSQL schema.
- Source and provider policies can change. This matrix must be reviewed again before enabling live transfers and at each documented acceptance.
